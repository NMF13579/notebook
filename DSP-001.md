# DSP-001 — Scaffolding Developer Specification Package

## 1. Вывод и package boundary

`DSP-001` связывает accepted Scaffolding Contract с одним exact implementation Task Brief. Он предназначен для human review и последующей передачи независимому coding agent после fresh repository preflight и отдельной Execution Authorization.

Этот package не владеет scaffold behavior и не дублирует его owner. При расхождении действует `AOS_SCAFFOLDING_CONTRACT_R1.md`; при расхождении exact implementation scope действует `Task-001-Scaffolding.md` только внутри contract boundary.

```text
Accepted contract
→ exact Task Brief
→ DSP identity/traceability package
→ human review
→ fresh target-repository preflight
→ separate Execution Authorization
→ execution
```

`READY_FOR_HUMAN_REVIEW` не означает `READY_FOR_EXECUTION`.

## 2. Exact implementation objective

Подготовить в `NMF13579/aos-3` воспроизводимую и recoverable infrastructure baseline: pinned Python/uv, one `./aos-dev` surface, strict scaffold manifest, preview-bound apply, journal/recovery, doctor/self-test, required negative fixtures и advisory CI — без Product Runtime behavior.

## 4. Accepted decisions and non-decisions

### Binding decisions

- target repository: `NMF13579/aos-3`;
- topology: modular monorepo, Product Runtime before Development Factory;
- first scaffold pins: CPython `3.14.6`, uv `0.12.1`;
- first-cycle runtime dependencies: none by default;
- development dependencies: pytest and Ruff, exact resolution owned by future reviewed `uv.lock`;
- primary local matrix: macOS/ARM64/zsh;
- independent CI matrix: Ubuntu 24.04/x86_64/bash;
- official development entrypoint: `./aos-dev`;
- `.aos/state/` and `.aos/records/` are preserved and not created by scaffold; only authorized setup may use the accepted `.aos/.scaffold/transactions/` journal boundary;
- authority defaults false; technical PASS is not approval.

### Candidate technical binding requiring exact Task/DSP review

- advisory GitHub Actions workflow path: `.github/workflows/ci.yml`.

This path fills a non-product implementation detail left unnamed by the accepted contract while preserving its advisory CI requirements. Rejecting this binding requires a corrected Task/DSP revision; coding agent must not choose another path during execution.

The package also makes one explicit operational reading of the accepted contract: its specific journal clauses in sections 6 and 11–12 create a narrow exception to the general no-Project-Memory-write rule. Only authorized `setup --apply` may create/use `.aos/.scaffold/transactions/`; `.aos/state/` and `.aos/records/` remain forbidden. Rejecting this reading requires correction of the contract before execution.

### Still separate or dynamic

- physical repository creation, access, visibility and branch protection;
- root `AGENTS.md` activation;
- observed root/branch/HEAD/worktree/remote;
- exact dependency lock digest;
- immutable CI action SHAs at execution date;
- network/sandbox capability;
- human-assigned Risk Profile;
- Execution Authorization and all Git permissions.

These are explicit preflight/decision bindings, not hidden assumptions.

## 8. Evidence and terminal report contract

Required Evidence is defined in Task section 8. Minimum review package after execution:

1. starting/ending repository identity;
2. accepted Task/DSP/contract identities;
3. planned and actual changed paths;
4. preserved out-of-scope state;
5. preview and journal identities;
6. `SCF-001…026` result table;
7. recovery state and remaining limitations;
8. exact checks run/not run;
9. Git operations all explicitly reported;
10. one next action and `stop: true`.

Temporary `.artifacts` is not durable authority. The Stage Report must name its Evidence locators and distinguish disposable output from immutable candidate files.

## 9. Recovery contract

The recovery owner is accepted contract sections 11–12. Task execution may only:

- resume an unchanged, preview-bound transaction;
- rollback files created by that transaction and exact captured managed preimages;
- preserve journal/staging when recovery fails;
- stop on changed identity, scope, permission or user-owned state.

It may not auto-retry after a material mismatch, delete unrelated/generated roots broadly or use Git reset/checkout as recovery.

## 13. Human review decision surface

Human review should decide only the exact candidate package:

- `ACCEPT` — accept exact Task/DSP revisions, without starting repository creation or execution;
- `NEEDS_CHANGES` — return named findings for a corrected `DOC-005` revision;
- `REJECT` — reject this implementation slice/package;
- `DEFER` — preserve candidates without acceptance or authorization.

After `ACCEPT`, next action remains a separate repository/preflight step and later H3 Execution Authorization. Acceptance must not be bundled with `Commit`, `Push`, `Merge` or `Release`.
