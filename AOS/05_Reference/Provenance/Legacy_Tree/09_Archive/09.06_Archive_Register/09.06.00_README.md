# 09.06 — Archive Register

## Назначение

Archive Register предназначен для навигации по архивным artifacts нового AOS.

Он должен позволять быстро определить:

- что архивировано;
- к какой категории относится artifact;
- почему он больше не active;
- был ли он когда-либо active;
- что его заменило;
- какие lessons сохранены;
- можно ли пересмотреть решение.

## Текущий этап

На текущем documentation stage автоматический registry не требуется.

Не нужно создавать:

- database;
- Control Plane;
- generated registry;
- lifecycle engine;
- approval service;
- background indexer;
- автоматическое перемещение файлов.

Достаточно будущей Markdown-oriented модели.

## Возможные поля записи

Запись может включать:

- archive identifier;
- artifact name;
- original path;
- archive path;
- category;
- reason;
- previous role;
- replacement path;
- decision reference;
- Git reference;
- lessons summary;
- reconsideration conditions;
- notes.

Это не означает обязательное использование YAML или конкретной schema.

## Категории

Регистр должен различать:

```text
SUPERSEDED
REJECTED
OBSOLETE
CLOSED_TEMPORARY
```

Не следует использовать неопределённый общий статус `ARCHIVED`, если он скрывает причину.

## Authority boundary

Archive Register является навигацией, а не authority source.

Если register и archived artifact противоречат друг другу:

- противоречие фиксируется;
- значение не угадывается;
- `UNKNOWN ≠ OK`;
- требуется review.

Register не может:

- создать approval;
- изменить lifecycle;
- назначить Risk Profile;
- разрешить execution;
- разрешить Git action;
- сделать archived artifact active.

## Отношение к `00_INDEX.md`

`00_INDEX.md` описывает active структуру проекта.

Archive Register описывает выведенные из active use artifacts.

Не следует смешивать их в единый registry до появления подтверждённой необходимости.

## Legacy boundary

Legacy sources не должны регистрироваться так, будто они были active artifacts нового AOS.

Для них используется `08_References`.

Допустима ссылка из register на relevant reference, если она объясняет происхождение lesson, но такая ссылка должна сохранять:

```text
authority: NONE
```

## Ручной режим

До появления реальной потребности register может поддерживаться вручную.

Manual before automation означает:

- сначала несколько реальных archive cases;
- затем проверка полезности полей;
- затем минимальная структура;
- только после этого возможна automation.

## Критерий будущей автоматизации

Автоматизация может рассматриваться, если:

- archive volume стал существенным;
- ручной поиск создаёт повторяющиеся ошибки;
- категории стабилизировались;
- fields подтверждены практикой;
- существует active owner;
- определены validation и failure behavior;
- automation не создаёт новую authority.
