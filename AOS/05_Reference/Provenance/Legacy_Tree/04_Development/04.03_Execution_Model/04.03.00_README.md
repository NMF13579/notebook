# 04.03.00 Execution Model

## Назначение документа

Execution Model определяет правила выполнения bounded Task в новом AOS.

Execution создаёт только то изменение, которое было определено и отдельно разрешено до начала работы.

## Legacy Reference Boundary

Материалы `NMF13579/AOS-FARM`, `AgentOS/AOS-1`, старые планы, отчёты, чаты и recovered artifacts используются только как `READ_ONLY_REFERENCE` с `authority: NONE` для нового проекта.

Из них разрешено извлекать:

- product intent;
- observable behavior;
- candidate contracts;
- повторяющиеся failure modes;
- доказанные lessons;
- полезные implementation ideas.

Из них нельзя автоматически переносить:

- active architecture;
- repository topology;
- Source of Truth;
- lifecycle или status;
- approvals;
- Risk Profiles;
- execution, Commit, Push, Merge или Release authorization;
- implementation readiness;
- незавершённые recovery chains;
- legacy complexity.

Любая идея из reference material становится частью нового AOS только после независимого анализа, явного описания в документации нового проекта и соответствующего human decision. Сходство с legacy не является основанием для принятия.

## Execution Boundary

Execution не включает:

- planning;
- изменение Scope;
- назначение Risk Profile;
- architecture approval;
- independent Validation;
- Review;
- Commit, Push, Merge или Release без отдельного решения.

Базовая схема:

```text
executable Task Brief
→ preflight
→ authorized change
→ Execution Report
→ stop
```

## Entry Conditions

До начала Execution должны быть известны:

- objective;
- expected result;
- repository;
- project root;
- branch;
- baseline;
- allowed scope;
- forbidden scope;
- validation expectations;
- stop conditions;
- permissions;
- execution authorization.

Если обязательный input отсутствует, Execution не начинается.

## Preflight

Минимальный preflight проверяет:

- правильный repository;
- правильный project root;
- ожидаемую branch;
- ожидаемый baseline;
- working tree;
- unrelated changes;
- доступность обязательных tools;
- соответствие permissions.

Preflight не исправляет findings.

На blocking finding создаётся report и stop.

## One Writer

Одна Task имеет одного writer.

Parallel write agents запрещены.

Read-only analysis может выполняться параллельно только для независимых вопросов и с последующим единым synthesis.

## Minimum Sufficient Change

Execution предпочитает минимальное изменение, которое полностью достигает expected result.

Не допускаются:

- opportunistic refactoring;
- массовое форматирование вне Scope;
- исправление unrelated defects;
- добавление framework «на будущее»;
- перенос legacy topology;
- изменение соседних contracts без необходимости.

## Protected Boundary

Если Execution обнаруживает необходимость изменить protected или canonical artifact:

1. finding фиксируется;
2. Scope не расширяется;
3. Execution останавливается;
4. требуется отдельный human checkpoint.

## Destructive Operations

Destructive operations требуют explicit human authorization, связанного с:

- конкретным target;
- конкретным действием;
- известными последствиями;
- текущим baseline.

Общее разрешение на «исправление» не разрешает reset, delete, history rewrite или irreversible external action.

## Network Boundary

Network access выключен по умолчанию.

Включение сети требует:

- явной необходимости;
- разрешённых источников;
- известных side effects;
- правил обращения с downloaded artifacts;
- контроля secrets.

Agent не расширяет network permissions самостоятельно.

## Unexpected Findings

Новый finding классифицируется как:

- blocking;
- non-blocking;
- unrelated;
- unknown.

Blocking finding завершает stage.

Non-blocking finding фиксируется как follow-up candidate.

Ни один finding не расширяет Scope автоматически.

## Execution Report

Execution Report содержит:

- task;
- stage;
- фактически выполненную работу;
- изменённые файлы;
- unmet requirements;
- findings;
- unknowns;
- checks, выполненные внутри разрешённого Scope;
- Git actions;
- одно следующее действие.

Execution Report не является Validation Report или approval.

## Git Boundaries

```text
Edit ≠ Commit
Commit ≠ Push
Push ≠ Merge
Merge ≠ Release
```

Execution completion не создаёт Git authorization.

## Terminal Results

Execution заканчивается одним из результатов:

- expected change created;
- BLOCKED;
- UNKNOWN_BLOCKED;
- interrupted;
- abandoned;
- blocking finding found.

После report работа останавливается.

## Критерий качественного Execution

Execution качественен, если candidate:

- ограничен Task Brief;
- имеет понятное происхождение;
- не смешивает stages;
- не скрывает unknowns;
- не переносит legacy state;
- готов к отдельной Validation.
